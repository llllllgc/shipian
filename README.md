# 拾片 0.5.1

从一个 JPG / RAW 混合文件夹看图选片，再原地分组整理。选片整理与匹配归档共用中央照片预览。

## 首页选片

1. 先把内存卡中的全部 JPG 和 RAW 导出到同一个文件夹。
2. 在首页选择“源文件夹”，自动展示 JPG 并关联 RAW。
3. 右侧点击“保留”或“不要”，自动进入下一张未决定的照片；“撤销”恢复上一步。左右键切图，1 / P 保留，2 / X 不要，Ctrl / Command + Z 撤销。
4. 全部 JPG 处理完且重名 RAW 候选确认后，点击“筛选”。

```text
源文件夹/
├── 已选 RAW/   保留的 JPG 对应 RAW
├── 未选 RAW/   不要的 JPG 对应 RAW
└── JPG/        全部 JPG
```

照片原地移动，不创建额外归档副本，不删除照片。原有子目录结构保留，避免重名覆盖。同一 RAW 对应多张 JPG 时，只要其中一张保留，该 RAW 就进入“已选 RAW”。

“未决定”不会被当作“不要”。同目录同名 RAW 优先关联；仍有多份候选时在右栏指定一份，或选择“仅整理 JPG”。缺少 RAW 的 JPG 仍集中保存；无对应 JPG 的 RAW 和其他文件留在原处，整理前显示数量。

标记与当前照片保存在源目录的隐藏 .拾片选片/ 中，重启自动恢复上次目录。整理中断后点击“继续筛选”，复用原位置与逐文件记录。整理开始后固定本次选择；开始前可在侧栏点击“重新扫描”，保留未变化 JPG 的标记。

## 图片和 RAW 预览

侧栏底部的“图片预览”可直接打开多张图片或整个文件夹，无须先匹配 JPG。支持 JPG、PNG、WebP、BMP、GIF，以及内置 LibRaw 能解码的 RAW。文件夹递归浏览，跳过隐藏路径和符号链接。

选片和归档都在窗口中央看图。照片下方可切换 JPG / RAW、缩放或打开大图，底部缩略图可翻片。在匹配归档中，右侧候选 RAW 旁的眼睛可将该候选显示在中央。双击匹配列表中的一行可返回该照片的中央预览。已归档的照片从归档读取，清理来源后仍能预览。

大图支持缩略图切换、左右方向键、放大/缩小、滚轮或触控板缩放、拖动、双击缩放和“适应”复位；Esc 关闭。左上角文件夹菜单可继续打开图片、文件夹或清理预览缓存。

RAW 预览在独立进程中生成，长边最多 2560 像素，按需缓存并复用；缓存预算 128 MB，自动移除较旧的预览。只写本机临时缓存，不在照片目录创建 JPG。预览采用基础渲染，不能作为原图像素级检查或专业调色的替代；正式 RAW 转图片仍按原分辨率输出。

## RAW 转图片

点击侧栏底部的“RAW 转图片”，选择保存位置与 JPG / PNG，开始批量转换。首页可选择整个 RAW 文件夹批量转换；匹配归档中仍可转换匹配的精选 RAW，并在来源清理后读取归档。

JPG 默认画质 90，可选 80、95、100；PNG 输出 8 位无损 RGB 图像。输出保持 RAW 相对目录，集中保存在所选位置的 RAW转图片/JPG_画质 或 RAW转图片/PNG。相同任务再次转换会校验并复用已有图片，同名且内容不符的文件跳过。同一目录下多种 RAW 共享文件名主体时，在输出名中保留 RAW 扩展名。

使用内置 LibRaw 0.22.2 解码完整 RAW，经白平衡、去马赛克和颜色转换后输出全尺寸图像，应用拍摄方向。Mac 使用 ImageIO，Windows 使用 WIC 编码；用户无需安装 Python 或其他转换软件。转换可取消，单张失败不影响其他照片；正常取消会清除临时输出，中断后的重试会清理记录中的遗留临时文件。

转换不改动 RAW，也不成为清理原 RAW 的依据。PNG 的无损指生成后的 RGB 像素，不能保留 RAW 的原始传感器信息。当前输出为基础渲染，颜色可能与相机直出或专业修图软件不同；不迁移完整 EXIF/XMP。扩展名可识别不代表所有相机、压缩变体均能解码，不支持的文件会逐项显示原因。

## 匹配归档

在左侧选择“匹配归档”可进入归档工作区，并继续已有任务。通过右上角的列表按钮可查看整批匹配结果。

1. 选择已选 JPG、全部 RAW 和保存位置。
2. 点击“匹配”，核对缺失与重名项目。
3. 点击“归档”，RAW/JPG 一起保存并逐文件做 SHA-256 校验。
4. 检查归档后点击“清理源文件”，核对完整源路径清单并确认。

清理仅包含完整归档的精选 RAW 和对应源 JPG，未选中、未匹配、未确认重名的文件保留。一组中 RAW 或任何对应 JPG 未完整归档，该组不进入清理名单。

确认清理会永久删除列出的源文件，不进入废纸篓 / 回收站。清理前再次核对源文件与归档；复核有异常时本次不删除任何源文件。

## 自动保存和继续任务

来源、重名选择、当前照片、筛选、搜索和处理进度保存在本机。正常退出前先完成保存；重启自动打开上次任务。归档工作区右上角的历史图标可打开历史任务或新建任务。

归档中断后点击“继续归档”，仍使用原目录。已完成文件校验后复用，不重复复制。向来源加入照片后点击“更新匹配”，再继续归档，只追加新文件或处理未完成项；已清理来源的旧照片也保留在同一任务中。

“打开归档”可导入已有 0.2 及以上 RAW/JPG 成对归档文件夹，无须再复制一遍。该目录需包含导出计划、处理记录和校验凭据。RAW-only 旧结果没有对应 JPG 的完整校验凭据，不能作为清理或恢复 JPG 的依据。

Mac 会保存所选目录的访问授权。授权失效时从任务菜单选择“授权目录”，重新选择原来的 JPG、RAW 和保存位置；任务记录保留，目录不能被静默替换为另一位置。

## 恢复原位置

清理后点击“恢复原位置”，软件从归档中恢复对应 RAW/JPG。开始前显示原路径和同名冲突：

- 原位置为空：校验归档后恢复，并保留原修改时间。
- 原位置已有相同内容：复用已有文件。
- 原位置已有不同文件、目录或链接：默认跳过，可以选择“另存副本”，生成不重名的恢复文件。

恢复会保留归档副本。同名文件不会被覆盖；归档校验失败的文件不会恢复。恢复中断后可从同一任务继续。

## 输出和记录

每个任务创建一个 精选归档_时间_随机标识 文件夹：

- RAW/、JPG/：精选文件，保留各自来源相对目录结构。
- 匹配清单.csv、处理记录.json：归档结果与校验凭据。
- 导出计划.json、逐文件记录.jsonl：任务快照与归档审计。
- 源文件清理记录.jsonl、源文件清理结果.json：清理记录。
- 源位置恢复记录.jsonl：恢复路径、同名处理和逐文件结果。

本机应用数据目录的 tasks-v1/ 保存任务状态及备份。元数据使用写入后替换和上一版备份，照片使用不覆盖提交。中断时可根据逐文件日志核对已完成操作；只有明确记录为本应用所有的未完成临时文件才会被清理。

源目录不会被自动删除。清理容量表示文件逻辑大小，实际可用磁盘空间受快照、压缩等文件系统行为影响。

## 匹配规则

按完整文件名主体匹配，处理大小写和 Unicode NFC。增加“_修图”等后缀后不自动匹配。多张 JPG 对应同一个 RAW 时 RAW 归档一次，所有 JPG 各自归档。跳过点号隐藏文件、目录和符号链接，目录读取失败时停止扫描。

匹配与归档按扩展名识别并原样复制；转换另由 LibRaw 判断能否解码，不影响原有归档能力。

## 开发与打包

基线：Flutter 3.47.8 / Dart 3.13.7。Mac 需要 Xcode，Windows 需要 Visual Studio C++ 桌面开发工具链。

```sh
flutter pub get
flutter analyze
flutter test
flutter run -d macos
zsh tool/build_macos.sh
```

Windows x64：

```powershell
powershell -ExecutionPolicy Bypass -File tool/build_windows.ps1
```

当前已完成 102 项自动测试。新增覆盖单文件夹关联、保留/不要/撤销、未决定阻断、全部 JPG 集中移动、RAW 分组、重名保护、整理取消与恢复、记录备份、自动恢复及两种窗口尺寸。包含可解码的合成 DNG 转 JPG / PNG 和 RAW 预览、方向旋转、中文路径、缓存复用与淘汰、预览取消、同名保护、进程终止、失败隔离、源变化保护和归档清理后访问。测试 DNG 由 tool/make_test_dng.py 生成，不使用个人照片。Mac 原生验收记录见 验证记录.md。

Windows 平台代码已同步，尚未在 Windows 机器上验收或生成安装包。Mac 包为本机 ad-hoc 签名测试包，尚无 Developer ID 外部分发签名与公证。

合成测试素材：

```sh
swift -module-cache-path /tmp/raw_picker_swift_cache tool/visual_assets.swift /tmp/raw_picker_demo
```

visual_assets.swift 生成的 RAW 为占位数据，仅供匹配测试；转换测试使用 test/fixtures/ 中的有效合成 DNG。参数换为 icon 可从 1024 像素主图重新生成 macOS 和 Windows 的各尺寸图标。

内置引擎源码及许可见 native/THIRD_PARTY.md。Mac 的 Xcode 构建阶段自动编译并签名转换程序，Windows CMake 自动构建并随应用分发。源码及 CDDL 许可同时包含在应用的 ThirdParty 资源目录中。
